## About GeoJSON

Take a look at the diagram below to get a better understanding of GeoJSON.

<Image src="https://blob-cdn.documentation.ai/org-6332b605-3e6a-4ce1-a00b-8a907a798c06/doc-12cb6eab-9bd9-48e3-96d6-1b96ec509835/1777393663679-pxkly1i1t4a-about_geojson.png?fm=auto&auto=compress%2Cformat" width="1402" height="1122" alt="" />

What it does is allow us to link specific locations or geometry with other elements such as text or numbers. We can also include other web-based elements like images, audio or video clips by uploading them to the web, and adding the link to the file in the GeoJSON.

---

## Key Terms

**GeoJSON&#x20;**&#x20;is a file type based on JSON (javascript object notation), which is specifically built for web-based applications.

**Geometry** is the coordinates of your data - the *where*

**Properties or Attributes** is the information *about* your location, or the links to other materials.

**Assets&#x20;**&#x61;re the other materials you might want to include.

## File Structures

This is boring, but important. When we are working together on our collaborative project, file structures are the single weakest point in transferring projects from one place to another. **File structures are how you organise your code, data and other assets.**

Most web map file structures look generally like this:

```typescript
my-web-map/
│
├── index.html              # Main webpage
│
├── css/
│   └── styles.css          # Layout + map styling
│
├── js/
│   └── script.js              # Map logic, data loading, interaction
│
├── data/
│   └── data.geojson      # Geographic data with attributes
│
├── assets/
│   ├── icons/              # Marker icons or symbols
│   └── images/             # Photos, logos, legends
│
└── README.md               # Documentation
```

This is a website, with four folders - **css/**, **js/**, **data/**, **assets/** - and in the main top level folder, an **index.html&#x20;**&#x61;nd a <a href="http://README.md" target="_blank" rel="noopener noreferrer">README.md</a> page.&#x20;

<Callout kind="tip" collapsed="false">
  If a file ends in / (i.e. icons/) this means that it is a **folder**. If it has a file extension, like .html, .md, .geojson or .png this means that it is a **file**. Look at the file structure above - can you tell the folders vs the files?
</Callout>

We will be setting up the **data side** of our web project today: &#x20;

```typescript
my-web-map/
│
├── data/
│   └── data.geojson      # Geographic data with attributes
│
├── assets/
│   └── images/             # Photos, logos, legends
│
└── README.md               # Documentation
```

This includes the basic README.md, a folder called **data/*****&#x20;***&#x77;here we will put our **data.geojson&#x20;**&#x66;ile, and a folder called **assets/** with two sub folders: **icons/** and **images/** where we will put our images.&#x20;

We will be using **Github**, which doesn't make it easy to set up a file structure. They generally expect you to do this on your laptop and *push* that structure to Git via the terminal, but we want to be doing something a little simpler, which also means a little backwards.

<Callout kind="info" collapsed="false">
  If you are familiar with desktop development (and dev servers), code editors like VS code and pushing to Git, you are more than welcome to do it that way. The reason we don't is because I cannot be certain that everyone will have the right packages installed or that their computers can do it - so we're staying in browser for now.
</Callout>

### Add image links

There are two kinds of links on the web: **absolute** and **relative**.&#x20;

An **absolute path or link** would link to where the file is in the whole file structure (i.e. would be the link to the image itself in your repository). This is great and the most stable option **where the location of your file will not change.&#x20;**&#x41;n absolute link looks like this: `https://www.parks.ca.gov/pages/712/images/SpanishFlatGoldMiners_circa%201852_CourtesyCA%20StateLibrary.JPG`

A **relative path or link**\*\*\* \*\*\*is a path described in relation to your file structure - specifically, where your geojson file is and where your image is. This is the best way to package up everything together **so your project can be moved from one place to another without breaking the code**. A relative link would look like this: `assets/images/tilden.jpg, `eventually deployed from an` index.html a`t the same level as the` README.md`

<Callout kind="alert" collapsed="false">
  Normally I'd ask you to use absolute links because it is easier. But since we will be working on a collaborative project, which eventually may be shipped over to State Parks, I'd like you to practice doing relative links.
</Callout>

<Steps>
  <Step title="Find your image on Github" title-type="p">
    In another tab, return to Github and find an image you'd like for the site.&#x20;
  </Step>

  <Step title="Determine the relative path" title-type="p">
    Look at the path for your image (where you originally made the folder). It should say `rop/assets/images/YOUR_IMAGE.jpg` or similar. Without the `rop/` this is the relative path.
  </Step>

  <Step title="Type or Paste as Attribute" title-type="p">
    Type or paste this path as an attribute for your image in your table. If you flick back to the geojson version it should look something like this:

    `{`

    `  "type": "Feature",`

    `  "geometry": {`

    `    "type": "Point",`

    `    "coordinates": [-122.241, 37.881]`

    `  },`

    `  "properties": {`

    `    "name": "Tilden Regional Park",`

    `    "type": "Park",`

    `    "image": "assets/images/tilden.jpg"`

    `  }`

    `}`
  </Step>

  <Step title="Rinse and repeat for all the columns" title-type="p">
    Now, continue until you've filled out all the columns for the site.&#x20;
  </Step>
</Steps>

### Export as geoJSON

When you're done, you're ready to export your GeoJSON for the final time.

Go to **Save** and choose **geoJSON**

Find the location of the *last* geojson you saved, and rename it `rop_YOURSITE.geojson`. Don't close the folder.
